# ymail-mcp

Рабочая почта Яндекса в Claude Code: чтение писем и черновики через IMAP.

Модель видит почту как набор инструментов — может найти письмо, прочитать переписку,
подготовить черновик ответа. **Отправлять письма она не может, и это сделано намеренно**
(см. ниже).

## Что умеет

| Инструмент | Что делает |
|---|---|
| `ymail_folders` | список папок аккаунта |
| `ymail_unread` | непрочитанное, по умолчанию 15 писем |
| `ymail_search` | поиск: по отправителю, теме, тексту, датам |
| `ymail_read` | письмо целиком по UID |
| `ymail_thread` | вся переписка вокруг письма |
| `ymail_draft` | создать черновик (в том числе ответ) |
| `ymail_trash` | переместить письмо в корзину |

Есть и командная строка для проверки без модели: `ymail folders`, `ymail unread`,
`ymail probe`.

## Почему нет отправки

Черновик человек просматривает и отправляет сам. Письмо, ушедшее коллеге или заказчику
по ошибке модели, отозвать нельзя — а черновик стоит ровно ноль. Если отправка
понадобится, добавить её несложно, но это осознанное решение, а не недоделка.

## Установка

Нужен [uv](https://docs.astral.sh/uv/). Зависимость всего одна — пакет `mcp`.

```bash
git clone <адрес репозитория> ~/projects/ymail-mcp
cd ~/projects/ymail-mcp
uv sync
```

## Доступ к почте

**Обычный пароль от аккаунта не подойдёт** — Яндекс требует пароль приложения.

1. Яндекс ID → Безопасность → Пароли приложений → Почта (IMAP).
2. Создать пароль, скопировать (показывается один раз).

Положить его в `~/.config/yandex-mail/.env`:

```
YMAIL_USER=имя@yandex.ru
YMAIL_PASSWORD=пароль-приложения
```

И закрыть от посторонних:

```bash
chmod 600 ~/.config/yandex-mail/.env
```

Это не формальность: сервер **проверяет права файла и отказывается работать**, если он
читаем не только владельцем. Вместо файла можно передать те же значения переменными
окружения — тогда файл не нужен.

Проверка, что доступ есть:

```bash
uv run --directory ~/projects/ymail-mcp ymail probe
```

## Подключение к Claude Code

```bash
claude mcp add ymail -- /path/to/uv run --directory ~/projects/ymail-mcp ymail-mcp
```

Либо руками в `~/.claude.json`:

```json
"ymail": {
  "type": "stdio",
  "command": "/home/<пользователь>/.local/bin/uv",
  "args": ["run", "--directory", "/home/<пользователь>/projects/ymail-mcp", "ymail-mcp"],
  "env": {}
}
```

Путь к `uv` должен быть полным: сервер запускается не из оболочки, и `PATH` там другой.

## Грабли, на которые уже наступили

- **Имена папок в IMAP приходят в modified UTF-7**: вместо «Отправленные» —
  `&BB4EQgQ,BEAEMEIu-`. Сервер их разворачивает сам, но если будете дописывать свои
  инструменты — помните.
- **При обзоре почты смотреть не только «Входящие».** Половина контекста переписки
  лежит в «Отправленных», и без них картина получается односторонней.
- **Поисковые запросы с кириллицей** уходят в IMAP в UTF-8 с явным указанием кодировки —
  наивная передача строкой не работает.

## Вместе с календарём: [ycal](https://github.com/sln-dns/ycal)

Почта редко живёт сама по себе: из письма рождается дело, у дела появляется срок, срок
превращается во встречу.

```
ymail_search "договор"        →  нашли письмо
ymail_read <uid>              →  прочитали, что просят
ycal todo add "Согласовать договор" --due 2026-09-18
ycal add "Обсуждение" --start "2026-09-18 14:00" --telemost
ymail_draft --reply <uid>     →  черновик ответа со ссылкой на встречу
```

**Пароли приложений у Яндекса раздельные по областям** — почтовый не подойдёт
календарю, и наоборот. Заодно раздельные конфиги дают отозвать один доступ, не трогая
второй.
